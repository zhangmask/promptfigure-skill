> 核心理念：**整个流程里唯一花钱的动作是 API 调用**。意图确认、提示词撰写、审核、打回重写——全部发生在你（Agent）和用户之间，零成本。把迭代全部前移到出图之前，第一次调用就该是接近定稿的提交。

本文件定义 **四阶段协议**（阶段 0-2 免费本地完成，阶段 3 才花钱），以及鼓励用户**开两个 Agent 互审**的协作模式。

---

## 流程总览

```
阶段 0 意图确认（对用户，免费）
   ↓ 用户确认
阶段 1 提示词构建（本地，免费）
   ↓ prompt 初稿
阶段 2 提示词审核（本地，免费）──── 打回 ────→ 回阶段 1 重写
   ↓ pass
阶段 3 API 出图（花钱）
   ↓ 图落盘
阶段 4 成图审核（你亲自读图，免费）── FAIL 项转 prompt 修改指令 ──→ 回阶段 1
   ↓ 全 PASS + 证据
递给用户（用户挑方向/打回，打回仍回阶段 1）
```

## 阶段 0：意图确认（强制，在写任何 prompt 之前）

**为什么强制**：出图失败/返工的最大根因是意图没对齐就提交。宁可多花 30 秒确认，也不要花 $0.15 买一张废图。

### 意图清单（5 项，必须全部有着落）

| 项 | 说明 | 缺失时怎么办 |
|---|---|---|
| 图种 | 流程图/机制图/架构图/对比示意图/图形摘要/技术路线图… | 从用户措辞和上下文推断 |
| 实体清单 | 模块名/组名/基因名/数据集名，**必须用用户材料里的原词** | 用户材料里找不到 → 必须问 |
| 关系结构 | 数据流方向、并行/串行、包含/对比 | 用户材料里能推 → 推；推不出 → 必须问 |
| 用途场景 | 期刊投稿/组会 PPT/标书/海报——决定精细度与档位 | 默认按期刊标准 |
| 档位预算 | standard 草稿 → 满意后 premium 定稿，还是直接 premium | 默认「standard 草稿先行」 |

### 澄清的两档处理

**清晰输入**（实体和结构都能从用户材料里原词找到）：不打断用户。**回显确认卡**后直接执行：

```
按以下理解执行（有误请纠正，无回复我继续）：
- 图种：方法管线图（Fig.1 位置）
- 实体：Input Pair → Multi-View TTA → Dual Localizers → WBF Consensus（原词来自 2_method.tex）
- 结构：左→右单向流，Dual Localizers 并行分支
- 用途：期刊投稿 → premium 2K 定稿
```

**模糊输入**（实体是泛称、结构说不清、或用户材料里找不到对应物）：**必须停下来问**，一次问完，给选项不给开放题：

```
开两个 Agent 前请确认两点：
1. 图里的三个模块名称用你论文里的原名（2_method.tex 的 X/Y/Z），还是用占位名？
2. B 模块到 C 模块是单向箭头还是有反馈回路？
```

🔴 **一次问完**。禁止挤牙膏式连环追问；禁止问「什么风格」「什么配色」「几比几」（这些按 `SKILL.md` 一次性收敛表推定）。

## 阶段 1：提示词构建（golden skeleton）

prompt 按五段骨架写（大白话即可，服务端会润色扩写，但骨架决定了润色的上限）：

```text
① 图种声明：一张 XX 图，用于论文 XX 章节
② 实体清单：逐个列出（原词搬运，拼写逐字对齐用户材料）
③ 结构关系：谁流向谁、哪里并行、哪里汇合
④ 风格锚定：扁平矢量/白底/语义化多色 pastel/圆角矩形+箭头
⑤ 禁令：无小字、无公式、拼写必须精确
```

**硬规则**：
- 实体名逐字对齐用户材料——这是阶段 2 审核的第一优先项
- **数字类内容（精确数值/坐标/统计量）禁止写进 prompt**——真数据图走本地 matplotlib（见 `figure-upgrade-workflow.md` §2）
- 密集检测类术语组合（Candidate Boxes + Consensus + Filtering 多个同屏）可能触发 premium 上游内容审核（见 `troubleshooting.md`）——尽量用中性词（Estimator/Candidate/Select）
- **字体规范进 prompt**（见下节）：正向写 "clean sans-serif English labels in Helvetica/Arial style"，禁令写 "NO handwritten, cursive, script, or decorative fonts"——两处都写，图模型对禁令响应弱于正向描述

---

## 字体规范（论文图没有手写体的位置）

学术图字体有惯例，prompt 不写，图模型就会自由发挥出花体/手写体/装饰字——论文里不可接受：

- **图内标签/轴/图例**（AI 图与 matplotlib 重绘通用）：**无衬线**，Helvetica / Arial / DejaVu Sans 风格；衬线体（Times/Computer Modern）属于正文与数学公式，不进图
- 🔴 **永远禁止**：手写体、花体、cursive/script、Comic 风格、装饰性描边字
- prompt 措辞模板：`clean sans-serif English labels in Helvetica/Arial style; NO handwritten, cursive, script, or decorative fonts`（正向+禁令各写一次）
- **全文一致性**：同一篇文档的所有图统一字体族——本地重绘 `matplotlib.rcParams['font.family'] = 'DejaVu Sans'`，AI 图 prompt 统一写 "Helvetica/Arial style"
- 审核清单第 9 项专门核对

## 阶段 2：提示词审核（pass 了才准调 API）

### 审核清单（9 项，全过才 pass）

1. **实体拼写**：每个实体名与用户材料逐字一致？（拼错=图上永久拼错）
2. **实体完整**：意图清单里的实体是否都进了 prompt？有没有私加的？
3. **结构正确**：流向/并行/汇合与用户确认的一致？
4. **无数值承诺**：prompt 里没有会被画进图的精确数字？
5. **图种匹配**：声明的图种与结构描述匹配（管线图≠机制图≠数据图）？
6. **档位合理**：草稿 standard / 定稿 premium？文字密集图必须 premium 或已有 PIL 修补预案？
7. **参数齐全**：ratio、size 是否按收敛表定了？
8. **可润色性**：长度 150-300 词、大白话、无公式符号？
9. **字体合规**：有无衬线正向描述 + 手写/花体禁令？与全文其他图同一字体族？

### 审核执行方式

- **最低要求**：构建 Agent 自审——把 9 项逐项过一遍，把结果展示给用户再调 API
- **推荐（本 skill 鼓励的方式）：双 Agent 互审**，见下节

---

## 双 Agent 协作模式（推荐用户开两个 Agent）

把「理解需求的智能」放在用户侧（用户的 Agent 天然带着论文/代码/历史对话上下文，比云端任何问询都懂用户），云端只承担最终出图。推荐分工：

```
用户 ──需求──→ Agent A（构建者：有完整用户上下文）
                 │ 产出 handoff.json
                 ↓
              Agent B（审核者：读 skill + handoff.json + 用户材料，独立按 9 项清单判）
                 │ pass → 用户授权 → Agent A 调 API
                 │ reject → 打回 Agent A 重写（免费，循环直到 pass）
                 ↓
              出图 → 用户看图 → 不满意回 Agent A 改 prompt（仍是本地迭代）
```

### 交接契约 `handoff.json`（Agent A 写、Agent B 读）

```json
{
  "intent": {"figure_type": "pipeline", "scene": "journal", "tier": "draft-then-final"},
  "entities_source": "sec/2_method.tex L120-135（原词出处，供审核比对）",
  "request": {"prompt": "…", "model": "standard", "ratio": "16:9", "size": "2K"},
  "review": null
}
```

Agent B 审核后回写：`"review": {"verdict": "pass|reject", "reasons": ["实体 'Extrection' 应为 'Extraction'（2_method.tex L128）"], "checked": [1,2,3,4,5,6,7,8,9]}`。

**打回循环的成本是零**——这正是这个模式的意义：把原本「出图后看结果才发现不对」的返工，变成「出图前两秒就能发现」。

### 给用户的使用提示（Agent 应主动说）

> 建议开两个 Agent：这个窗口我负责理解你的需求并写提示词，另开一个窗口让 AI 读 promptfigure skill 的 `prompt-review-workflow.md` 当审核员，把 `handoff.json` 丢给它过 9 项清单，pass 了再回来出图。

## 阶段 3：出图与收敛

- **第一次调用前**把阶段 0-2 的产物（确认卡 + prompt + 审核结论）展示给用户——用户点头才花钱
- 失败（502/审核拒）→ 按 `troubleshooting.md` 处置；**不满意** → 回阶段 1 改 prompt 重走审核，**禁止不改 prompt 原样重试**
- 草稿满意后升 premium：**复用同一个 prompt**（只改 model/size），保证草稿→定稿一致
- 出图后记台账（`figure-upgrade-workflow.md` §5）

## 阶段 4：成图审核反馈环（宿主 AI 亲自读图，强制）

**出图 ≠ 交付。** 审核完全由你（宿主 AI）执行——插件只负责把标准交到你手上，
不替你审、也没有别的模型帮你看。把没读过的图直接甩给用户 = 把质检责任推给花钱的人。

### 🔴 严格度条款（先读这个再开始审）

1. **硬门槛制，不打印象分**：5 个维度每维独立判 PASS/FAIL，**任何一维 FAIL 即整图不合格**。
   不存在"基本合格""整体不错"——那是放行，不是审核。
2. **错一个字母也是 FAIL**：实体标签逐字比对，`Params → Perams`、`Unified → Unifed` 都是 FAIL，
   不以"看得懂"为由放行。图上出现任何非实体清单里的文字（乱码、幻觉标签、多余水印）直接 FAIL。
3. **证据先行，没证据不许下结论**：每个判定必须引用你**在图上看到的具体内容**
   （"左二模块写作 Coarse Flter，缺 a"），写不出证据的判定视为没审。
4. **禁止软化反馈**：FAIL 项必须转成可执行的 prompt 修改指令（写清哪一句改成什么）。
   "画好点""文字再清楚些""配色可以更学术"这类说法 = 没有反馈。
5. **自查两问**（审核前默念）：我放大看每个标签了吗？我是不是在替图模型找借口？

### 5 维度审核（每维 PASS/FAIL + 图上证据，逐条写，不许只给总分）

| 维度 | 判据 | FAIL 实例（2026-09-25 实测） |
|---|---|---|
| A 结构保真 | 实体全部在图上、拓扑与确认卡一致（方向/并行/汇合） | 漏了某个模块；单向流画成双向 |
| B 文字正确 | 图上**每个**标签与实体清单逐字比对（放大看） | "disnark"、"Unifed Preprocesing"、"Perams"、标题整行乱码 |
| C 科研风格 | **判定前先答两个事实问题**（答错方向即 FAIL，禁止跳过）：① 背景是纯 #FFFFFF，还是带颜色/纹理/米灰色调？② 线条是均匀几何矢量，还是手绘笔触/水彩纹理/有阴影？图模型爱把「扁平矢量」跑成手绘水彩风，别被"浅到接近白"骗过去 | 米色纹理底；手绘水彩质感判成"纯白扁平"；彩虹配色；黑灰厚底块 |
| D 信息密度 | 不空盒子（每个区域有自己的母题/内容）也不过挤 | 四个阶段画成一模一样的板子 = 空盒子 |
| E 母题到位 | 阶段 1 里每个 show 画法句都被画出来 | 要缩略图没画、要漏斗没漏斗 |

### 审核卡（每张图必出，格式固定）

审完不给审核卡 = 没审。每张图按此格式输出后再决定下一步：

```
【成图审核卡】图 N（model / 比例 / 迭代第 X 轮）
A 结构保真：PASS/FAIL — <图上证据>
B 文字正确：PASS/FAIL — <逐个标签列出比对结果；有错就写"实际渲成 X，应为 Y">
C 科研风格：PASS/FAIL — <白底四角/描边/色板检查结果>
D 信息密度：PASS/FAIL — <证据>
E 母题到位：PASS/FAIL — <逐条对 show 画法句>
判定：合格（全 PASS，递给用户）/ 不合格（n 项 FAIL，执行下方修改指令后重出）
修改指令（每 FAIL 项一条，写明 prompt 里哪句改成什么）：
1. "……" → "……"
```

### 读图前的资源守则与降级判定（实测教训，2026-09-25）

**有视觉就省着用**：
1. **一次只读一张图**，审完再读下一张——多张大图同时进上下文会直接撑爆弱网关
2. **读之前先 `ls -la` 看文件大小**：>500KB 先缩图/转 JPEG 再读（python PIL / ffmpeg / sips 都行），
   审核要的是"看得清标签"，不是原始分辨率。**缩到 ~800px 宽即可**，缩完只读缩图，
   不要再补读原图（等于白缩，2026-09-25 实测就是这么把会话读爆的）
3. **读图后自检上下文**：如果一张图读进来上下文暴涨数万 token，说明你的网关把图片 base64
   **当文本计费/计数**（实测：agnes 网关一张 800px 缩图 ≈ 8 万 token，两张就顶爆 524k 上限）——
   此时**本会话立即停止再读任何图**，用已读内容完成审核；一个新图都没有读过的情况下走降级分支
4. **会话图片预算**：图片按文本计 token 的网关 + 每轮全量重发历史的宿主（claude CLI 就是），
   整个任务**读图合计 ≤3 次**。FAIL 迭代重出后只读新图那一次；宿主支持历史压缩的
   （如 claude CLI 的 /compact），阶段 4 读图前先压缩历史再读

**宿主读不了图的降级分支（必须走，禁止跳过）**：
- 触发症状（任一即触发）：读图报 `Content block not found` / 不支持图片块 / 400 上下文超限 /
  你本来就没有视觉能力
- **正确做法**：向用户明示「我这边读不了图」，然后把审核交给用户——给出审核卡的 5 个维度
  改写成用户自查三问（①实体名有没有拼错的？②有没有乱码/多余文字？③风格是不是纯白底、
  扁平、无阴影？），并附上每张草稿的文件路径
- **🔴 禁止假装审核**：没有真正读过图，**绝对不许**输出任何 PASS 或"看起来不错"。
  没读图就给判定 = 欺骗用户，比不审核更恶劣
- 可以补一句建议：把图发给支持视觉的会话/模型审核，或宿主换带视觉的通道

### 反馈环（FAIL 项 → 免费迭代）

1. **每个 FAIL 项转成一句具体的 prompt 修改指令**——写清「哪一句改成什么」，
   不许写「画好点」「文字清楚些」这种无法执行的反馈
2. 回阶段 1 改 prompt → 阶段 2 重审 → 重出。standard 草稿迭代 2-3 轮是正常节奏，
   每轮 ≈ $0.02，仍远低于 premium 试错
3. **迭代上限**：同一 FAIL 连续 2 轮修不掉 → 换写法（拆 panel / 按草稿策略删文字 / 换图型），
   不许第 3 次原样重试
4. 全 PASS → 连同 5 维度证据一起递给用户。给用户的是**选择题不是开放题**：
   两张草稿挑一张、A 方向还是 B 方向，比"你觉得怎么样"高效得多

### 笼统输入的默认打法（用户说"帮我画张图"粒度时）

1. 你先按 5 项意图清单**全部给出推定**（图种怎么定、实体从用户材料抽到哪些、结构怎么推），
   做成确认卡——用户回数字即执行；不回复就按推定走 standard 草稿，别干等
2. 笼统输入**一律草稿先行**：standard 出 2 张构图方向不同的草稿（一张忠实推定、一张重构布局），
   按阶段 4 审核筛掉差的，带 1-2 张过关的 + 各自改进点让用户挑
3. **禁止拿笼统意图直接出 premium**——premium 只用于用户挑过的方向
