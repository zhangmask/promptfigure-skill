> 核心理念：**整个流程里唯一花钱的动作是 API 调用**。意图确认、提示词撰写、审核、打回重写——全部发生在你（Agent）和用户之间，零成本。把迭代全部前移到出图之前，第一次调用就该是接近定稿的提交。

本文件定义 **四阶段协议**（阶段 0-2 免费本地完成，阶段 3 才花钱），以及鼓励用户**开两个 Agent 互审**的协作模式。

---

## 流程总览

```
阶段 0 意图确认（对用户，免费）
   ↓ 用户确认
阶段 1 提示词构建（本地，免费）
   ↓ prompt 初稿
阶段 2 提示词审核（本地，免费）──── 打回 ────→ 回阶段 1 重写
   ↓ pass
阶段 3 API 出图（花钱）─── 失败/不满意 → 回阶段 1 改 prompt（不是无脑重试）
```

---

## 阶段 0：意图确认（强制，在写任何 prompt 之前）

**为什么强制**：出图失败/返工的最大根因是意图没对齐就提交。宁可多花 30 秒确认，也不要花 $0.15 买一张废图。

### 意图清单（5 项，必须全部有着落）

| 项 | 说明 | 缺失时怎么办 |
|---|---|---|
| 图种 | 流程图/机制图/架构图/对比示意图/图形摘要/技术路线图… | 从用户措辞和上下文推断 |
| 实体清单 | 模块名/组名/基因名/数据集名，**必须用用户材料里的原词** | 用户材料里找不到 → 必须问 |
| 关系结构 | 数据流方向、并行/串行、包含/对比 | 用户材料里能推 → 推；推不出 → 必须问 |
| 用途场景 | 期刊投稿/组会 PPT/标书/海报——决定精细度与档位 | 默认按期刊标准 |
| 档位预算 | standard 草稿 → 满意后 premium 定稿，还是直接 premium | 默认「standard 草稿先行」 |

### 澄清的两档处理

**清晰输入**（实体和结构都能从用户材料里原词找到）：不打断用户。**回显确认卡**后直接执行：

```
按以下理解执行（有误请纠正，无回复我继续）：
- 图种：方法管线图（Fig.1 位置）
- 实体：Input Pair → Multi-View TTA → Dual Localizers → WBF Consensus（原词来自 2_method.tex）
- 结构：左→右单向流，Dual Localizers 并行分支
- 用途：期刊投稿 → premium 2K 定稿
```

**模糊输入**（实体是泛称、结构说不清、或用户材料里找不到对应物）：**必须停下来问**，一次问完，给选项不给开放题：

```
开两个 Agent 前请确认两点：
1. 图里的三个模块名称用你论文里的原名（2_method.tex 的 X/Y/Z），还是用占位名？
2. B 模块到 C 模块是单向箭头还是有反馈回路？
```

🔴 **一次问完**。禁止挤牙膏式连环追问；禁止问「什么风格」「什么配色」「几比几」（这些按 `SKILL.md` 一次性收敛表推定）。

## 阶段 1：提示词构建（golden skeleton）

prompt 按五段骨架写（大白话即可，服务端会润色扩写，但骨架决定了润色的上限）：

```text
① 图种声明：一张 XX 图，用于论文 XX 章节
② 实体清单：逐个列出（原词搬运，拼写逐字对齐用户材料）
③ 结构关系：谁流向谁、哪里并行、哪里汇合
④ 风格锚定：扁平矢量/白底/语义化多色 pastel/圆角矩形+箭头
⑤ 禁令：无小字、无公式、拼写必须精确
```

**硬规则**：
- 实体名逐字对齐用户材料——这是阶段 2 审核的第一优先项
- **数字类内容（精确数值/坐标/统计量）禁止写进 prompt**——真数据图走本地 matplotlib（见 `figure-upgrade-workflow.md` §2）
- 密集检测类术语组合（Candidate Boxes + Consensus + Filtering 多个同屏）可能触发 premium 上游内容审核（见 `troubleshooting.md`）——尽量用中性词（Estimator/Candidate/Select）

## 阶段 2：提示词审核（pass 了才准调 API）

### 审核清单（8 项，全过才 pass）

1. **实体拼写**：每个实体名与用户材料逐字一致？（拼错=图上永久拼错）
2. **实体完整**：意图清单里的实体是否都进了 prompt？有没有私加的？
3. **结构正确**：流向/并行/汇合与用户确认的一致？
4. **无数值承诺**：prompt 里没有会被画进图的精确数字？
5. **图种匹配**：声明的图种与结构描述匹配（管线图≠机制图≠数据图）？
6. **档位合理**：草稿 standard / 定稿 premium？文字密集图必须 premium 或已有 PIL 修补预案？
7. **参数齐全**：ratio、size 是否按收敛表定了？
8. **可润色性**：长度 150-300 词、大白话、无公式符号？

### 审核执行方式

- **最低要求**：构建 Agent 自审——把 8 项逐项过一遍，把结果展示给用户再调 API
- **推荐（本 skill 鼓励的方式）：双 Agent 互审**，见下节

---

## 双 Agent 协作模式（推荐用户开两个 Agent）

把「理解需求的智能」放在用户侧（用户的 Agent 天然带着论文/代码/历史对话上下文，比云端任何问询都懂用户），云端只承担最终出图。推荐分工：

```
用户 ──需求──→ Agent A（构建者：有完整用户上下文）
                 │ 产出 handoff.json
                 ↓
              Agent B（审核者：读 skill + handoff.json + 用户材料，独立按 8 项清单判）
                 │ pass → 用户授权 → Agent A 调 API
                 │ reject → 打回 Agent A 重写（免费，循环直到 pass）
                 ↓
              出图 → 用户看图 → 不满意回 Agent A 改 prompt（仍是本地迭代）
```

### 交接契约 `handoff.json`（Agent A 写、Agent B 读）

```json
{
  "intent": {"figure_type": "pipeline", "scene": "journal", "tier": "draft-then-final"},
  "entities_source": "sec/2_method.tex L120-135（原词出处，供审核比对）",
  "request": {"prompt": "…", "model": "standard", "ratio": "16:9", "size": "2K"},
  "review": null
}
```

Agent B 审核后回写：`"review": {"verdict": "pass|reject", "reasons": ["实体 'Extrection' 应为 'Extraction'（2_method.tex L128）"], "checked": [1,2,3,4,5,6,7,8]}`。

**打回循环的成本是零**——这正是这个模式的意义：把原本「出图后看结果才发现不对」的返工，变成「出图前两秒就能发现」。

### 给用户的使用提示（Agent 应主动说）

> 建议开两个 Agent：这个窗口我负责理解你的需求并写提示词，另开一个窗口让 AI 读 promptfigure skill 的 `prompt-review-workflow.md` 当审核员，把 `handoff.json` 丢给它过 8 项清单，pass 了再回来出图。

## 阶段 3：出图与收敛

- **第一次调用前**把阶段 0-2 的产物（确认卡 + prompt + 审核结论）展示给用户——用户点头才花钱
- 失败（502/审核拒）→ 按 `troubleshooting.md` 处置；**不满意** → 回阶段 1 改 prompt 重走审核，**禁止不改 prompt 原样重试**
- 草稿满意后升 premium：**复用同一个 prompt**（只改 model/size），保证草稿→定稿一致
- 出图后记台账（`figure-upgrade-workflow.md` §5）
