# 成图质量标准（升级 / 拼版 / 对照类交付必读）

> **适用范围**：凡是你**动手改了原图的像素或布局**的工作——A1 数据图重绘、A2 示意图升级、A3 结构组合、对照图/多图拼版、论文截图裁插。纯 AI 新建图的审核走 `prompt-review-workflow.md` 阶段 4 的 A–E 五维；本文件管「优化已有图」的质量，两者在阶段 4 审核卡里**叠加执行**。
>
> **为什么有这个标准**：把几张原图拼在一起 ≠ 优化。下面三条定义就是「优化」二字的可判定含义——每条都能在成图上找到 PASS/FAIL 证据。禁止凭印象宣称「已优化」「已美化」。

---

## 0. 动手前的三个前置（缺一个就不许动图）

1. **先说论点，再动图**：用一句话写出这张图在原文里**论证什么**（如「Ours 的分割边界比两个基线更细」「我们的方法在无参考帧上仍稳定」）。写不出来 = 还没读懂这张图的上下文，先回去读原文相应章节，禁止动图——没读懂就动手，是样式反复返工的第一根因。
2. **先判体裁**：这张图是**结果对比图**（展示效果差异：before/after、ours vs 基线）还是**方法图**（讲结构/流程）？
   - **结果对比图**的展示惯例是底线：必带输入对照（无 GT 的定性对比也要有输入行/列）、行列标签语义真实、同类内容同尺度。重排可以，剥掉这些惯例让图不可解读 = FAIL。
   - **方法图**的惯例：直线箭头、阶段边界清晰；顶会方法图几乎不用拐弯箭头，别画蛇添足。
   - **混合体裁是最常见的翻车源**：在对比图上画流程箭头、在方法图上标结果数据，读者就会误读。一张图里两种信息都要时，分区呈现并让两种区域视觉可区分。
3. **写 acceptance 四项**（留痕载体见 §3）：
   - `story`：读者该记住的一句话
   - `segmentation`：阶段/区块怎么分的、论据块如何与流程块区分
   - `alignment`：谁和谁同尺度、共享什么网格
   - `enhancement`：做了哪些白名单内增强 + 具体参数

---

## 1. 三定义（每条可判 PASS/FAIL，交付前逐条过）

1. **视觉对齐** = 同类内容同尺度 + 共享网格。
   - 同类内容（人脸/曲线/柱组/切片）跨卡跨 panel 必须**同一显示尺寸**、同一处理方式；禁止同类东西一张占满卡、另一张缩成邮票。
   - 所有 panel 共用一套边距/间隙/行高网格；照片卡与图表卡混排时，用同一底色/描边语言框住。
   - FAIL 例：拼版后卡 1 的脸占满 400px、卡 2 同源的脸只有 120px。
2. **合理的分段** = 阶段边界跟**论证结构**走，不跟「我手上有什么图」走。
   - 动机/论据块与流程块必须视觉可区分（小标题措辞或图层语言区分），否则读者把论据当成流程的第三步——语义错误比不美观严重。
   - 相邻块之间箭头宣称的「流向」必须为真：块 2 里的内容必须真的来自块 1（同一数据/同一样本），禁止「A 样本的输入 → 箭头 → B/C/D 样本的输出」这种断裂拼接。
3. **按原文思维优化** = 优化方向由原文图注决定，不由「AI 擅长什么」决定。
   - **动哪里**：原文图注强调的差异，在成图上**更容易看到**了吗？（图注说「边界更细」→ 边界差异有没有被放大 inset / 对齐摆放突出）
   - **不动哪里**：原文的展示惯例（输入对照、行标语义、配对结构）原样保留。
   - **反例**：原文论点是边界更细，你却去给图加彩色底纹——方向错了，做得越多偏得越远。不是所有图都需要美化；选择「不动」有时是正确决策。

## 2. 优化档位：什么时候美化、美化什么（L0/L1/L2）

动手前对每个候选缺陷问一句：**这是显示问题还是内容问题？**

| 档位 | 做什么 | 什么时候选 |
|---|---|---|
| **L0 原样引用** | 不加工，只需裁剪/缩放到位 | 内容本身成立、只是要插进文档；原图是矢量或高清；评审存档场景（忠实性优先）。**大多数 A1 数据图按 §3 重绘达标后就不需要再动**——别为了「显得做了事」去加戏 |
| **L1 排版美化** | 重排、拼版、裁剪、对齐、取材重选 | 原材料没问题但**布局**不行：多图拼版、论文裁片重组、拼版后尺度不齐、网格散乱 |
| **L2 呈现增强（声明制）** | 只许白名单内动作，做了必须写进 `enhancement` | 有明确显示层缺陷且 L1 解决不了 |

**L2 白名单**（✅ 只许做清单内的，❌ 之外一律禁止）：

- ✅ 对比度/伽马拉伸（**必须声明区间**，如「1–99.5 百分位拉伸」）
- ✅ 放大 inset、行内小标、排版对齐
- ✅ 结构编辑：裁剪、重排、选样（选样理由写进台账 `note`）
- ❌ **清晰度提升 / 超分 / 去噪**——低分辨率源无源可提，硬提 = 造假
- ❌ 改子图内容像素、❌ AI 重绘论文成品图表、❌ 用生成模型「补全」数据区域

**禁止虚报**：宣称「优化」的每一条都要能对应到白名单里的具体动作 + 参数；写不出动作和参数的「优化」= 没发生，从交付里删掉。

## 3. 留痕（挂进已有强制载体，不新增流程）

1. **figure-ledger.json**（`figure-upgrade-workflow.md` §5）：升级/拼版/restyle 类 entry 增加 `acceptance` 字段（前置第 3 步写的四项），enhancement 写成数组。
2. **阶段 4 审核卡**：升级/拼版/对照类交付，在 A–E 五维之外**追加三行**（每行先写实况再判 PASS/FAIL）：
   ```
   F 视觉对齐：实况=<同类内容各卡尺寸/网格实况> → PASS/FAIL
   G 合理分段：实况=<区块划分与论证结构的对应、流向是否为真> → PASS/FAIL
   H 按原文思维：实况=<原文论点一句话 + 本次优化如何服务该论点> → PASS/FAIL
   ```
3. **round-vN.md**「优化前 → 优化后」表：「改了什么」列必须写白名单内动作 + 参数（如「1–99.5 百分位拉伸」），禁止写「变好看」「更清晰」。

**一票否决**：enhancement 里有白名单外动作、acceptance 四项缺失、F/G/H 任一 FAIL → 该图不许交付，转修改指令回炉。
