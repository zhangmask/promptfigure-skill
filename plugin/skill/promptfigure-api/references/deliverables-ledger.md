# 每轮交付与台账（round deliverables & ledger）

> 场景：每次用 promptFigure 出图 / 优化图片 / 整文批处理结束后，宿主 AI 必须按本文件产出结构化交付。
> 目的：用户随时能回答三个问题——**这轮做了什么图、图插在原文哪里、用了什么上下文/数据**。
> 🔴 本文件是硬性协议：缺任何一项 = 交付不完整。CLI 优先——全程用 `pf` 命令沉淀状态，GUI 只留给人「看一眼 / 点审批」。

---

## 0.  CLI 优先原则（2026-09-25 定规）

- 出图、核验、审批、定稿全链路都有 CLI：`pf open → craft → render → qa → review resolve → premium`，**能用 CLI 就用 CLI**
- GUI 只用于两件事：人亲眼看图、人点审批。插件的门禁与留痕都挂在 CLI 上，走 CLI 的每一步都可审计
- 每轮结束的交付目录里，路径一律引用**用户本机真实路径**（相对当前交付目录优先，跨目录用绝对路径），禁止只给「见图库」这类指不到文件的话

---

## 1. 交付目录结构（每一轮 = 一个新文件夹）

在**用户当前工作目录**（论文旁边）建 `promptfigure-out/`，每轮交付新建递增版本文件夹：

```
promptfigure-out/
├── v1/                          ← 第 1 轮交付（每次交付新建一个，v1 → v2 → v3…）
│   ├── round-v1.md              ← 本轮反馈（见 §2 必含项）
│   └── figures/                 ← 本轮产出的图（文件名带版本号）
│       ├── fig-method-v1.png
│       └── fig-method-v2.png    ← 改版后重新出，旧版保留可回溯
├── v2/round-v2.md               ← 第 2 轮……
├── paper-with-figures.md        ← 不断演进的「论文 + 已插图」版（见 §3）
└── final/                       ← 最终论文版本（见 §4，仅最终成稿时建）
    ├── paper-final.md
    └── paper-final.docx         ← 格式副本，按用户原文档格式（见 §4）
```

- 版本号判断：`ls promptfigure-out/` 取最大 N + 1；用户已有自己的目录约定时听用户的
- `figures/` 里的图**永不覆盖**：同一张图的每个版本都是独立文件（`-v1/-v2/…`），旧版要能随时打开对比

## 2. round-vN.md 必含项（本轮反馈）

模板（每轮照此填，没有的项目写「无」并说明原因，禁止静默省略）：

```markdown
# 第 N 轮交付 · YYYY-MM-DD HH:mm

## 本轮清单
| # | 图 | 图种 | 档位 | 版本 | 本机路径 | 插入位置（§¶） | 状态 |
|---|---|---|---|---|---|---|---|
| 1 | 方法流程图 | pipeline | premium | v2 | figures/fig-method-v2.png | §2 ¶1 ↔ §2 ¶2 之间 | 已审批 |

## 插入位置（图放在原文哪两段之间）
逐张图给出——**上一段最后一句 + 「……」 + 下一段第一句**，让用户一眼定位：

> ……la optimización por enjambre de partículas ajusta automáticamente los principales parámetros.……La estrategia de aumento de datos incluye recorte aleatorio, jitter de color y deformación elástica.
> （图 1 插在上述两句之间，即 §2 ¶1 末 ↔ §2 ¶2 首）

- 自然段为粒度（¶），不用句号硬切；原文没有下一段时注明「§2 段末，文末」

## 所用上下文（只放首尾句，中间省略）
- 原文上下文：「首句……尾句」（禁止整段贴入；用了哪几段就列哪几条，§¶ 标清楚）
- 引用范围声明：本次生成具体使用了 §2 ¶1–¶2（明确到段，供用户核对）

## 数据与引用
- 本地表格/数据文件：[table1.csv](../data/table1.csv)、[run_exp2.m](../code/run_exp2.m) —— **只给引用链接，不内联内容**
- 参考图：refDataUrl（本地图 /path/to/ref.png）或 refUrl（https://…）；用了就标，没用写「无」

## 优化前 → 优化后（仅「优化已有图」任务）
| 图 | 优化前 | 优化后 | 改了什么 | 所用上下文（首尾句） |
|---|---|---|---|---|
| 原图1（曲线组） | figures/orig/fig1-old.png | figures/fig1-v1.png | 色板改语义化、字号 8pt、去 3D | 「首句……尾句」 |
```

> 🔴 **「改了什么」列必须写具体动作 + 参数**（成图质量标准 L2 白名单内动作，如「1–99.5 百分位拉伸」「同类 panel 统一到 360px 高」），禁止写「变好看」「更清晰」这类无参数宣称——写不出动作和参数的「优化」= 没发生，删掉该行。升级/拼版类每张图还要在 figure-ledger.json 的 entry 里带 `acceptance` 四项（见 `figure-upgrade-workflow.md` §5）。

**三条填写铁律**：
1. **上下文只放首句 + 尾句，中间一律省略号**——整段进 MD 会让用户无法快速审阅，也让版本 diff 爆炸
2. **表格 / 代码 / 数据文件一律引用链接，禁止内联内容**——内联会让 MD 迅速腐烂、版本更新时无法对账；要「看见这轮用了什么」，点链接就是
3. **每张图必须看得到版本**（文件名 `-vN` + 清单里的版本列 + 状态列）——版本是回溯和 diff 的唯一坐标

## 3. paper-with-figures.md（不断演进的呈现版）

- 结构 = 用户原文的章节树；**本轮涉及的段落**照录，**不涉及的段落**一律省略为一行：`……（§3 全文见原文）`
- 每张图插在自己的插入位置（§2 ¶1 ↔ ¶2 之间），图片用相对路径引用 vN 文件夹里的真实文件
- 每次交付**更新同一个文件**（或在文件名带版本 `paper-with-figures.vN.md` 保留历史）——用户随时打开这一个文件就能看到「论文现在长什么样」

---

## 4. final/ 最终论文版本

用户要求「最终成稿 / 定稿」时才建，包含：

1. `final/paper-final.md`——最终呈现版（全部已审批图就位、引用与上下文清单汇总）
2. `final/paper-final.<用户格式>`——**格式副本，按用户原文档格式来**：
   - Word/.docx → 交付 .docx（有 pandoc/docx 工具就用；无工具要明说「做不了格式副本，交付 MD」）
   - LaTeX/.tex → 交付 .tex（图用 `\includegraphics` 引用真实路径，结构可编译）
   - WPS → 交付 .docx（WPS 可直接打开）
   - 🔴 **副本必须能正常打开**：交付前自己验证（文件非零、结构完整、能找到图）；验证不了就明说，禁止交一个打不开的坏副本

## 5. 最终成稿流程（用户说「定稿 / 最终版」时按此走）

1. **先提醒核对**：提醒用户「数据有没有更新？要不要重新跑一次核验？」——用户明确确认后，才进入 premium 最终定稿
2. **确认高级定稿**：向用户复述「将消耗 premium 档额度出高清定稿，N 张」并取得确认；未确认不动手
3. **定稿后问矢量图**（衔接 SKILL.md 阶段 5）：
   - 提醒成本：矢量图由**用户自己的 AI 本地重绘**，token 消耗大、速度慢
   - 🔴 **比赛 / 数学建模 / 学术会议竞赛：默认不做**，速度优先；只有时间充裕才做
4. **用户确认做矢量图时**：首选**比照着重绘**——拿最终版用本地工具照着画，每个模块、箭头、标签独立成对象；🔴 **必须用支持图层分离的工具编辑**：PPT/WPS 用单独形状或组合、SVG 用 `<g>` 分组、Illustrator/Inkscape 用独立图层——一把糊成扁平对象 = 不可编辑，返工。应用按用户主要偏好来（PPT / WPS / 其他）。**退路=描摹**（vtracer 等）：先核对数值与比例（数值差不多即可、对应关系必须对），交付时明确告知「描摹件、文字已变路径不可直接编辑」——不许当可编辑矢量宣称

## 6. 自检清单（每轮交付前过一遍）

- [ ] 版本文件夹新建（vN 递增）、图带版本号、旧版未覆盖
- [ ] round-vN.md 五项齐：清单 / 插入位置（两段边界句）/ 上下文（首尾句）/ 数据引用（链接）/ 优化前后（如适用，改了什么 = 动作+参数）
- [ ] 升级/拼版/对照类图：figure-ledger.json entry 带 `acceptance` 四项；enhancement 无白名单外动作；阶段 4 审核 F/G/H 三维全 PASS
- [ ] paper-with-figures.md 已更新到含本轮所有图
- [ ] 路径全部指得到真实文件（md 里的链接点得开）
- [ ] final/ 仅在最终成稿时出现，格式副本已验证可打开
